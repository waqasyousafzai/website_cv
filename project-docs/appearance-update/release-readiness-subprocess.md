# Release Readiness - Subprocess

## Preconditions, Scope, and Evidence

Begin after the approved outputs and implementation from lifecycle points 1–6 are complete. Reconcile their acceptance criteria, recorded handoffs, intentional departures, and unresolved limitations with the checked-out candidate before testing. Do not infer a new visual direction directly from the inspiration sources.

This subprocess owns final verification, release-blocking stabilization within the approved requirements, and the release record. It does not own a redesign, new product behavior, CV-content changes, dependency or architecture changes, or deployment setup. A fix that would change an approved design decision, route purpose, data or simulation semantics, public shared-component API, or hosting strategy must return to the owning lifecycle stage rather than being silently absorbed here. Cloudflare deployment is not configured; this subprocess verifies the locally built Vite artifact with `npm run preview`, not a hosted environment.

Record the completed run under an `## Release Verification` heading in this file. Include the verification date and commit; relevant uncommitted application-source changes; browser; preview command and URL; exact CSS-pixel viewports and motion setting; each quality-gate result; a route-and-interaction result matrix; defects found, fixes made, and checks repeated; and every accepted departure or limitation with its rationale, user impact, and follow-up owner. Mark anything not runtime-verified as such rather than assuming it passes.

[ ] 1. Establish the release candidate and finite verification checklist. Confirm that lifecycle points 1–6 are approved, account for every outstanding handoff or known limitation, and record the baseline metadata before changing source files.
[ ] 2. From the repository root, run `npm run format`, `npm run lint`, `npm run check`, `npx tsc --noEmit`, and `npm run build`. Record each exit result and failure; do not treat the Vite build as a substitute for the separate TypeScript check.
[ ] 3. Serve the generated artifact with `npm run preview` and test `/`, `/pipeline`, and `/replay` at `390×844` and `1440×900`. For each route and viewport, enter the URL in a fresh browser context and hard-reload it so the check covers production-preview deep linking rather than only client-side navigation. Inspect the browser console and required asset requests, page and pane scrolling, responsive layout, and focus visibility.
[ ] 4. Exercise the release flows with pointer and keyboard. On `/`, wait for the boot sequence to complete and verify separate **Initialise** and Enter navigation paths. In the shared shell, verify route navigation and current-route state plus both contact entry points, dialog focus containment, Escape and close-control dismissal, focus restoration to the exact opener, submission feedback, and toast dismissal. On `/pipeline`, run all seven `RUN_ORDER` stages to completion and check node selection and callout actions, both inspector tabs, Live tail, both fit modes, the CV download and feedback, logs, progress, status, and ticker output. On `/replay`, select every history row and both metric tabs, exercise recording play/pause when available or verify the designed fallback, and confirm **Re-run this dag** starts a fresh run at `/pipeline` and consumes `?run=true` exactly once.
[ ] 5. Repeat the motion-bearing flows with `prefers-reduced-motion: reduce`. Confirm that continuous and decorative movement stops or resolves immediately while the timed boot information, pipeline execution and live-state updates, replay content, controls, status, and feedback remain available. Confirm there is no uncaught runtime error, unexpected console error, missing required asset, unintended document-level horizontal overflow, overlap, clipped essential control or text, unreachable route content, or regression in the intended graph, log, inspector, and page scroll regions.
[ ] 6. Classify as release-blocking any failed quality gate, unmet approved acceptance criterion, uncaught runtime error, missing required asset, or defect that makes essential content or a required pointer or keyboard path unusable. Resolve in-scope blockers, rerun each affected scenario and gate, then repeat all five quality gates and the production-preview smoke pass after the final source change. Return out-of-scope defects to the owning lifecycle stage and keep the candidate blocked until they are resolved or explicitly accepted as non-blocking.
[ ] 7. Complete the release record. Review the two deliberate departures documented in `README.md` for continued accuracy, correct them there if needed, and record all other accepted visual or behavioral departures and non-blocking limitations in this file with rationale and impact. Do not mark the candidate ready while a release-blocking defect, unreviewed departure, or unexplained skipped check remains.

## Acceptance Criteria

- The `## Release Verification` record contains the required reproducible baseline, quality-gate and browser results, fixes and reruns, departures, limitations, and skipped or source-confirmed checks. It identifies the exact tested candidate and does not present an unverified state as passing.
- `npm run format`, `npm run lint`, `npm run check`, `npx tsc --noEmit`, and `npm run build` all exit successfully after the final source change without requiring further source edits.
- The production preview directly loads and hard-reloads `/`, `/pipeline`, and `/replay` at both `390×844` and `1440×900`, with no uncaught runtime errors, unexpected console errors, missing required assets, unintended document-level horizontal overflow, overlap, clipped essential content, unreachable route content, or regression in intended pane scrolling.
- On `/`, the progressive boot log reaches its complete state and separate checks confirm that both **Initialise** and Enter navigate to `/pipeline`; the panel remains reachable when its content exceeds the viewport.
- The shared shell links navigate to the correct route and expose the matching current state. Both contact controls open the same named dialog; focus remains contained while it is open; Escape and the close control dismiss it; focus returns to the exact opener; and submission produces the existing dismissible success toast.
- On `/pipeline`, a run advances all seven `RUN_ORDER` stages to completion with corresponding node, edge, log, progress, status, and ticker feedback. Node selection and callout close/**Open in inspector** actions, Stage/Schema tabs, Live tail, Actual size/Fit to view, and CV download operate as labelled without making graph or inspector content unreachable.
- On `/replay`, the recording loads and its Play/Pause control works or the designed fallback is usable; every run-history selection updates the associated metadata and log; Throughput/Run duration updates the labelled chart content; and **Re-run this dag** starts a fresh pipeline run, replaces `/pipeline?run=true` with `/pipeline`, and does not restart on reload, back, or forward navigation.
- Every required pointer interaction has a keyboard-operable path with a logical focus order and visible focus. Dialog focus returns to its opener, selection and status are not conveyed only by color, and reduced-motion mode suppresses continuous or decorative animation without hiding information or stopping the underlying boot, pipeline, live-data, or replay behavior.
- Every accepted visual or behavioral departure from the reference is documented with a concise rationale and user impact; the two existing `README.md` departures are reviewed and remain accurate or are corrected. Every deliberately accepted non-blocking limitation is documented with its impact and follow-up owner.
- No known release-blocking defect, unreviewed departure, unexplained skipped check, or unresolved out-of-scope blocker remains. Readiness applies to the locally built and previewed artifact; it does not claim that Cloudflare deployment or production-host deep-link fallback has been configured or verified.
